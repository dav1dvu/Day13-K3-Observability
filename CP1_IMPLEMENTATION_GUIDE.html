🛠️ Implementation Details

1. CorrelationIdMiddleware (app/middleware.py)

Purpose: Generate/extract and propagate correlation ID across all requests

app/middleware.py

Key Features:

  • Clear contextvars to prevent data leakage between requests
  • Extract correlation ID from x-request-id header
  • Generate new UUID if not provided: req-<8-char-hex>
  • Bind to structlog contextvars for automatic inclusion in logs
  • Add correlation ID to response headers

Flow:

Request ↓ Headers check: x-request-id? ↓ [No] → Generate: req-<8-char-hex> [Yes] → Use provided value ↓ bind_contextvars(correlation_id=...) ↓ Process request ↓ Add to response headers: • x-request-id • x-response-time-ms

Example Usage:

// Client sends request with custom ID
GET /chat
Headers: x-request-id: req-custom01

// API response includes ID
Headers:
  x-request-id: req-custom01
  x-response-time-ms: 151

// All logs for this request contain:
"correlation_id": "req-custom01"

2. Log Enrichment (app/main.py - /chat endpoint)

Purpose: Add request context to all logs for better tracking and debugging

app/main.py - chat() function

Enriched Fields:

Field Source Purpose

session_id Request body Group requests in same session
feature Request body Identify feature (qa, summary, etc.)

3. PII Scrubbing (app/logging_config.py)

Purpose: Automatically redact sensitive data before writing logs

app/logging_config.py - configure_logging()

Protected Patterns:

Type Pattern Replacement
Email [\w\.-]+@[\w\.-]+\.\w+ [REDACTED_email]
Vietnamese Phone (?:\+84|0)(?:[ .-]?\d){9} [REDACTED_phone_vn]
ID Card (CCCD) \d{12} [REDACTED_cccd]
Credit Card \d{4}[- ]?\d{4}[- ]?\d{4}[- ]?\d{4} [REDACTED_credit_card]

Code Change:

structlog.configure(
    processors=[
        merge_contextvars,
        structlog.processors.add_log_level,
        structlog.processors.TimeStamper(fmt="iso", utc=True, key="ts"),
        scrub_event,  # ← Enabled
        structlog.processors.StackInfoRenderer(),
        structlog.processors.format_exc_info,
        JsonlFileProcessor(),
        structlog.processors.JSONRenderer(),
    ],
)

}

4. Global Exception Handler (app/main.py)

Purpose: Catch and log unhandled exceptions with proper context

app/main.py - global_exception_handler()

Features:

  • Catch all unhandled exceptions
  • Log error with correlation_id, error_type, and details
  • Record error metrics
  • Return 500 response with correlation_id

Code:

@app.exception_handler(Exception)
async def global_exception_handler(request: Request, exc: Exception):
    error_type = type(exc).__name__
    record_error(error_type)
    log.error(
        "unhandled_exception",
        service="api",
        error_type=error_type,
        payload={"detail": str(exc)},
    )
    return JSONResponse(
        status_code=500,
        content={
            "detail": "Internal server error",
            "correlation_id": getattr(
                request.state, "correlation_id", "unknown"
            ),
        },
    )

📚 Key Concepts

Correlation ID Format

Format: req-<8-char-hex>

Examples:

  • req-a1b2c3d4 (auto-generated)
  • req-custom01 (from client header)

Contextvar Binding

Uses structlog's contextvars to automatically include bound variables in all logs within that request context.

bind_contextvars(
    correlation_id="req-xyz",
    user_id_hash="abc123"
)

log.info("event")
# Result: {"correlation_id": "req-xyz", "user_id_hash": "abc123", "event": "event"}

User ID Hashing

Use SHA256 to hash user IDs for logging without exposing actual user identifiers:

hash_user_id("u_team_01")
# Result: "2701c69e592d" (first 12 chars of SHA256 hash)

❓ Troubleshooting

Correlation ID always "MISSING"

Cause: Middleware not properly installed

Fix: Ensure app.add_middleware(CorrelationIdMiddleware) is called

Context variables not in logs

Cause: bind_contextvars() not called before logging

Fix: Call bind_contextvars() early in request handling

PII not being scrubbed

Cause: scrub_event processor not enabled

Fix: Uncomment scrub_event in configure_logging()

Response time always 0ms

Cause: Time calculation error

Fix: Use time.perf_counter() for accurate measurements
